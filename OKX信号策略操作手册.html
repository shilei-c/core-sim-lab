把 CORE 攻守兼备版策略接入 OKX 自动交易

EMA5/34 金叉 · 不加仓 · 0.8ATR 止损 · 40% 宽移动止损 · 无冷却 · 操作手册

先看结论

OKX 的「创建策略」里没有能填 EMA / ATR 参数的自定义策略编辑器。它的策略是模板化的（网格、定投、信号、套利等），无法直接把这套规则填进去。

唯一能承载这套逻辑的是 「信号策略 / Signal Bot」：买卖逻辑用 TradingView 的 Pine Script 写好，OKX 生成一个 Webhook 地址，警报触发时 OKX 按信号下单——逻辑在 TradingView，OKX 只管执行。

⚠️ 两个前提必须先接受：① 信号策略只支持永续合约，不支持现货（你网站回测的是现货）；② TradingView 发 Webhook 需要付费订阅。

⚠️ 现货回测 ≠ 永续合约实盘

你的网站回测基于现货、收盘价成交、固定手续费滑点。OKX 信号策略只能跑永续合约，会额外引入：

  • 杠杆与强平：价格剧烈波动时可能爆仓，本金归零——现货不会。
  • 资金费率：多空每 8 小时结算一次，长期持仓有额外成本或收入。
  • 信号延迟：TradingView 警报 → Webhook → OKX 下单有秒级延迟，激进策略下滑点可能远超回测假设。
  • 止损触发时机：Pine Script 的止损通常在 K 线收盘/实时刷新时判断，不等于逐笔实时挂单。

因此即便逻辑一致，实盘结果也不会复刻网站收益表。务必先用模拟盘（Demo Trading）跑至少一个月。

整体链路

1 写策略在 TradingView 用 Pine Script 实现这套规则 → 2 建信号OKX 生成 Webhook 地址 + signalToken → 3 配警报把地址与令牌填进 TradingView 警报 → 4 建机器人OKX 创建信号策略机器人并绑定信号。

数据来源与步骤依据：OKX 官方帮助中心《Trading Signal Bot FAQs》《How to set up signal trading bot with TradingView》，检索于 2026-11-25（平台功能可能更新，以 App 内实际界面为准）。

第一步：Pine Script 策略代码

打开 TradingView → 图表底部 Pine 编辑器 → 粘贴下面代码 → 保存并添加到图表。图表周期必须设为 4 小时（4H），否则 EMA/ATR 的根数口径全错。

//@version=5
strategy("CORE 攻守兼备版 EMA5/34 + ATR/移动止损", overlay=true,
     initial_capital=10000,
     default_qty_type=strategy.percent_of_equity,
     default_qty_value=98,
     pyramiding=0,
     process_orders_on_close=true,
     commission_type=strategy.commission.percent,
     commission_value=0.08,
     slippage=3)

// ---------- 参数（对应网站回测）----------
fastLen     = input.int(5,    "快线 EMA",   minval=1)
slowLen     = input.int(34,   "慢线 EMA",   minval=1)
rsiLen      = input.int(14,   "RSI 周期",   minval=1)
atrLen      = input.int(14,   "ATR 周期",   minval=1)
atrMult     = input.float(0.8,  "ATR 止损倍数",  minval=0.1, step=0.1)
trailPct    = input.float(40.0, "移动止损回撤%", minval=0.1, step=0.5) / 100
cooldownB   = input.int(0,    "冷却 K 线数", minval=0)
rsiEntryMax = input.float(82.0, "入场 RSI 上限", minval=1, maxval=100)
rsiExitMin  = input.float(84.0, "离场 RSI 阈值", minval=1, maxval=100)

// ---------- 指标 ----------
emaF = ta.ema(close, fastLen)
emaS = ta.ema(close, slowLen)
rsiV = ta.rsi(close, rsiLen)
atrV = ta.atr(atrLen)

golden = ta.crossover(emaF, emaS)   // 金叉
death  = ta.crossunder(emaF, emaS)  // 死叉

// ---------- 状态 ----------
var int   cooldown = 0     // 剩余冷却 K 线
var int   adds     = 0     // 已加仓次数
var float peak     = 0.0   // 持仓期最高价

inPos = strategy.position_size > 0
avgPx = strategy.position_avg_price

// 更新持仓期最高价（移动止损基准）
if inPos and high > peak
    peak := high

// 刚平仓（信号或止损）→ 进入冷却
if strategy.position_size[1] > 0 and not inPos
    cooldown := cooldownB
    peak := 0.0
    adds := 0

// 入场：金叉 + RSI<82 + 空仓 → 满仓(98%)，不加仓
if golden and rsiV < rsiEntryMax and not inPos
    strategy.entry("Long", strategy.long)
    peak := close
    adds := 0

// 离场：死叉 / RSI 超买 → 全平
if (death or rsiV > rsiExitMin) and inPos
    strategy.close("Long")

// 风控：0.8ATR 止损 与 40% 移动止损，取更近者挂单
if inPos and avgPx > 0
    s1 = avgPx - atrMult * atrV
    s2 = peak > 0 ? peak * (1 - trailPct) : s1
    strategy.exit("Stop", "Long", stop=math.max(s1, s2))

// 冷却递减
if cooldown > 0
    cooldown -= 1

// ---------- 绘图 ----------
plot(emaF, "EMA5",  color=color.orange, linewidth=2)
plot(emaS, "EMA34", color=color.blue,   linewidth=2)
plotshape(golden, "金叉买", shape.triangleup,   location.belowbar, color=color.green, size=size.tiny)
plotshape(death,  "死叉卖", shape.triangledown, location.abovebar, color=color.red,   size=size.tiny)

代码严格沿用网站引擎参数：EMA5/34、RSI14、ATR14、入场 RSI<82、离场 RSI>84、0.8×ATR 止损、最高价回撤 40%（宽移动止损让利润奔跑）、满仓 98%、不加仓、卖出无冷却。滑点按 3 tick（约 0.03%）近似，手续费按 0.08%。这套参数在 CORE 上涨段捕获约 54% 涨幅，同时在下跌年仍取得正收益，兼顾进攻与防守。

第二步：OKX 端创建信号

1
进入信号策略
登录 OKX → 顶部「交易」→「策略交易」→「创建策略」→ 选「信号策略」→ 创建。
想先零风险测试：切到「模拟交易 Demo Trading」，里面同样有策略交易 → 信号策略，Webhook 地址与实盘不同，别混用。
2
新增自定义信号
点「新增自定义信号」→ 填信号名称（如 CORE-EMA5-34）和简介 →「创建信号」。
3
复制两个关键值
系统会生成 Webhook URL（实盘通常是 https://www.okx.com/algo/signal/trigger，模拟盘是 https://www.okx.com/pap/algo/signal/trigger）和 signalToken。这两个填进 TradingView 警报，token 不要公开。
4
选消息格式
OKX 提供「TradingView 策略格式」和「通用格式」。上面代码用了 strategy.entry()，选前者，直接复制它给出的 JSON 模板即可（占位符会自动替换）。模板长这样，把 signalToken 换成你的：
{
  "id": "{{strategy.order.id}}",
  "action": "{{strategy.order.action}}",
  "marketPosition": "{{strategy.market_position}}",
  "prevMarketPosition": "{{strategy.prev_market_position}}",
  "instrument": "{{ticker}}",
  "signalToken": "把这里换成OKX生成的signalToken",
  "timestamp": "{{timenow}}",
  "maxLag": "60",
  "investmentType": "base",
  "amount": "{{strategy.order.contracts}}"
}

第三步：TradingView 端设置警报

1
确认周期与合约
图表周期设为 4H；交易对选永续合约（如 COREUSDT.P），不是现货 COREUSDT。策略添加到图表后点开齿轮可微调参数。
2
创建警报
顶部工具栏点「警报」→ 条件选刚添加的策略 → 频率选「仅订单成交时（Order fills only）」→ 到期选「无限制」。
3
填消息与 Webhook
「消息」框粘贴上一步的 JSON 模板；「通知」勾选 Webhook，粘贴 OKX 给的 Webhook URL → 创建。
4
验证链路
在 TradingView 的「警报日志」和 OKX 机器人的「Events History」里核对是否收到信号；报错会显示在 Events History，常见是 instrument 格式或 maxLag 超时（可把 maxLag 调大到 120）。

第四步：OKX 端创建机器人

  • 回到信号策略页，点你的信号旁的「创建机器人」。
  • 交易对：加入你要跑的永续合约（如 CORE-USDT-SWAP）。没选的交易对，信号会被过滤、不下单——这是最常见的"信号不执行"原因。
  • 杠杆：建议先用低杠杆（如 1–2×）跑模拟盘。合约杠杆会放大回撤并带来强平风险。
  • 投入金额：设独立预算，机器人的仓位与你的主账户隔离，坏信号不会波及主仓位。
  • 仓位口径：消息里 investmentType="base" + {{strategy.order.contracts}} 表示按 Pine 回测算出的合约张数下单；Pine 里的 98%/50% 仓位与 OKX 实际投入是两套口径，实盘以机器人设置为准。想简化，可改用固定金额模式，每笔投固定 USDT。
  • 安全阀：建议在机器人端另设一个固定百分比止损作为兜底——TradingView 一旦宕机或 Webhook 失败，你的持仓不会被自动保护。

必须知道的局限

问题说明
只支持永续合约OKX 官方 FAQ 明确：Signal Bot 目前不支持现货、杠杆理财和交割合约。五币里若某币没有永续合约，就无法用这条路。
Webhook 要付费TradingView 免费版不能发 Webhook，需 Essential 及以上（约 $12.95/月起，按年付）。OKX 与 TradingView 有合作，达标交易量可能获赠 Plus 套餐。
一信号一机器人每个信号只能绑定一个机器人；一个机器人可加多个交易对。不同币共用一套参数，无法逐币分别优化。
止损非逐笔实时Pine 的止损依赖 K 线收盘或实时 bar 刷新，可能与交易所逐笔挂单的触发价、时点不同；剧烈行情下差异会被放大。
不会复刻回测收益信号延迟、滑点、资金费率、杠杆强平、K 线内路径差异，都会让实盘偏离网站收益表。网站收益是理想化上限。

更省事的替代方案

如果只想按这套规则手动操作、不想碰合约和付费订阅：直接用你网站顶部的实时信号面板——它已经把同一套规则推进到当前，给出五币"买/卖/持有/观望"、持仓成本、ATR 止损位、移动止损位、距止损百分比和 4H 收盘倒计时。

看点亮的「已收盘确认」信号，在 OKX 现货手动下单，止损位照面板数字设。这样和回测口径一致（现货、无杠杆），也没有强平风险，代价是要自己下单、盯止损。
